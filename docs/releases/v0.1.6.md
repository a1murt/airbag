**Undo for AI coding agents.** Airbag snapshots your project before each shell command Claude Code, Codex, Cursor,
Gemini CLI or GitHub Copilot CLI runs that can change files, so a deleted folder, a `git reset --hard` or a wiped
`.env` is one click back.

### Install or upgrade

```bash
brew install --cask a1murt/airbag/airbag
```

Already installed: `brew upgrade --cask airbag`.

Or download `Airbag-0.1.6.dmg` below, drag Airbag to Applications and open it. Releases are not notarized yet (there
is no Apple Developer ID): each one is built and ad-hoc signed from its tag by this repository's public release
workflow. From the DMG, macOS asks once on first launch (macOS 15 and later: System Settings → Privacy & Security →
Open Anyway; macOS 14: right-click → Open). The Homebrew cask checks the SHA-256 of that same build and clears its
quarantine flag, so macOS doesn't ask; `brew upgrade` may say that the signer changed, which is expected for an
ad-hoc signed build.

### Guard: what it could not read

Before the public launch, a review of Guard found commands that reached your home folder while Guard read them as
harmless. Each one is now blocked or waits for you:

- a program name built at run time: `"$(which rm)" -rf ~`, `${RM:-rm} -rf ~`, a variable set to such a lookup;
- a tilde that brace expansion produces: `rm -rf ~{,}` (the shell expands braces first, tildes after);
- a link made earlier in the same line: `ln -s ~ x && rm -rf x/*`;
- options before find's start point: `find -x ~ -delete`;
- the home folder computed in inline code: `shutil.rmtree(os.environ['HOME'])` in `python3 -c`, the same in
  `node -e` and `ruby -e`;
- a command padded until the check took longer than the hook's 4 s limit, which then answered "allow".

A few commands now always wait for you, also where other risky commands are only recorded:

- a delete that starts at the root of the disk if a variable is empty: `rm -rf "$DIR/"*`;
- emptying a folder Airbag cannot determine: `cd "$DIR" && rm -rf *`;
- a program whose name is only known at run time, handed your home folder or a system folder.

Also:

- `airbag allow` refuses to run inside an agent's session, whatever the binary is called.
- Until Guard has decided, the hook's 4 s watchdog refuses the command. A shell command over 1 MiB is refused
  unchecked.
- Deleting `.jj`, `.hg`, `.svn` or a nested repository's `.git` asks first: snapshots never hold version-control
  history.
- `source`, `. script`, `gh pr checkout`, `sort -o`, `yq -i` and a few other writing forms now get a snapshot.

### Guard: a second, adversarial pass

Then a red team tried to get past Guard on purpose. What it found is now blocked or waits for you:

- code that `source` or `.` reads from stdin, a here-string or a process substitution, and `bash <(…)`:
  `source /dev/stdin <<< 'rm -rf ~'` is read like `sh -c`;
- zsh's `=rm`, the `~+` tilde and operators such as `${HOME%/}` on a known value; `~-` and `~1`, folders Guard can't
  know, wait for you;
- locking instead of deleting: `chmod 000 ~`, `chflags uchg ~/.ssh`, `chmod u-r ~/.aws`;
- `plutil`, or inline `node -e` or `python -c` code, rewriting an agent's hook settings;
- deleting, replacing or locking Airbag's app or its `airbag` command, which now waits for you;
- brace expansions and lines built to exhaust the check: after 1.5 s of analysis the command waits for you.

Secrets no snapshot holds are now guarded too. Deleting, overwriting, emptying or locking an SSH private key or
`authorized_keys`, `~/.aws/credentials`, GnuPG private keys, `~/.kube/config` or a keychain is blocked, and adding a
key to `authorized_keys` asks. `~/.ssh/config`, `known_hosts` and public keys work as before.

Replaying 5,090 commands from real agent sessions changed no decision against 0.1.5. The fuzzer in CI also fails now
on a check slower than 2 s. ADR-042 and ADR-043 have the details.
